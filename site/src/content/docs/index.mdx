## It asks niri, then acts through niri

An agent such as Claude Code, Codex or Pi starts `niri-computer-use serve` and gets niri's own view of your desktop: windows, workspaces, focus, monitors, screenshots that map back to the layout, and, where apps expose them, accessible buttons and fields. Once it takes the lease, it can focus windows, start apps you listed, resize and move them with niri's actions, click, drag, scroll, type and paste, and open three Noctalia panels.

## Measured in a nested niri

The test suite runs niri, Noctalia and real apps in a headless nested session and checks what each app received, event by event.

- 100 of 100 clicks by element landed on the right GTK 4 button. [Accessibility results](https://github.com/ayagmar/niri-computer-use/blob/main/docs/results/m9.md)
- A stop mid-drag ended the call `stopped` and released the mouse button. [Input results](https://github.com/ayagmar/niri-computer-use/blob/main/docs/results/m4.md)
- Noctalia's control center was seen open 50 to 51 ms after the call. [Noctalia results](https://github.com/ayagmar/niri-computer-use/blob/main/docs/results/m5.md)

## One engine, one gate before every action

Your agent starts the server over stdio, and every client on one niri shares one engine. Looking goes straight to niri, `grim`, the accessibility bus or Noctalia. Acting passes the gate first: the lease, the stop flag, the screen's lock state and your deny list.

## The stop key is yours

<div class="columns">
<div class="column">

- One agent at a time holds the lease, and only the lease holder acts. Looking needs no lease.
- A key bound to `niri-computer-use stop` cancels the running action and takes the lease back. An agent can't press it.
- No input goes out while the screen is locked or its lock state is unknown. The server won't type into a window the agent didn't name, send input to apps you deny, or click at pixels of a stale screenshot.
- It starts apps only from presets you write, unless you turn on [`unrestricted`](concepts/configuration/#unrestricted).
- It won't fill or press a password field, and it withholds clipboard copies a password manager marks as secret.
- Every action reports `accepted`, whether niri took the request, and `observed`, what niri saw afterwards. Nothing is retried.
- Every call goes to an audit log, without the text typed, the clipboard, window titles or images.

None of this is a sandbox. A click or a key can do anything you could do, and screenshots show the agent whatever is on your screen. Read [Safety](concepts/safety/) before you let an agent act.

</div>

## What it needs, and where it stops

<div class="columns">
<div class="column">

### Needs

- niri 26.04 on Linux. With any other niri version the server only looks.
- `grim`, `wtype`, `loginctl` and libxkbcommon.
- Rust 1.99.0 through rustup, to build it. There is no package yet.
- Claude Code, Codex, Pi or any client that starts a stdio MCP server.
- Optional: [Noctalia](concepts/noctalia/) 5.2 for its panels and lock state, and an accessibility bus (at-spi2-core) for elements.

</div>
<div class="column">

### Limits

- The pointer tools need one monitor at transform `Normal`. The keyboard, screenshots and the other tools work with any monitors.
- niri 26.04 gives only floating windows a place on screen that elements can be measured from. On a tiled window, `activate_element` and `set_element_text` work, but a click by element doesn't.
- Accessibility varies by toolkit. GTK 4 works; GTK 3 and Qt apps that draw their own title bar give no element boxes.

</div>

## Install

From a shell inside your niri session:

<Steps>

1. Build and install the server.

   ```sh
   git clone https://github.com/ayagmar/niri-computer-use.git
   cargo install --locked --path niri-computer-use
   ```

2. Check it against your session. `niri.compat` should be `ok`, and every entry under `binaries` `true`.

   ```sh
   ~/.cargo/bin/niri-computer-use status
   ```

3. Register it in your agent. For Claude Code:

   ```sh
   claude mcp add --scope user niri-computer-use -- ~/.cargo/bin/niri-computer-use serve
   ```

   [Client setup](start/clients/) covers Codex, Pi and other MCP clients.

4. Give your agents the skill, which tells them how to use the tools. From the directory you cloned:

   ```sh
   mkdir -p ~/.claude/skills ~/.agents/skills
   ln -s "$PWD/skills/niri-computer-use" ~/.claude/skills/niri-computer-use
   ln -s "$PWD/skills/niri-computer-use" ~/.agents/skills/niri-computer-use
   ```

5. Bind the stop key, inside the `binds` block of `~/.config/niri/config.kdl`, with the path `cargo install` printed:

   ```kdl
   Mod+Shift+Escape allow-inhibiting=false allow-when-locked=true hotkey-overlay-title="Stop the AI agent (niri-computer-use)" { spawn "/home/you/.cargo/bin/niri-computer-use" "stop"; }
   ```

</Steps>

Then try a [first session](start/first-session/): ask your agent to look, then to act.

</Workspace>
