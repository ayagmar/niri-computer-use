## It asks niri, then acts through niri

An agent such as Claude Code, Codex or Pi starts `niri-computer-use serve` and gets niri's own view of your desktop: windows, workspaces, focus, monitors, screenshots that map back to the layout, and, where apps expose them, accessible buttons and fields. Once it takes the lease, it can focus windows, start apps you listed, resize and move them with niri's actions, click, drag, scroll, type and paste, and open three Noctalia panels.

## One gate before every action

Your agent starts the server over stdio. By default every client on one niri is served by one engine; a client in [standalone mode](concepts/configuration/#shared) runs its own and still shares the lease and the stop flag. Looking goes straight to niri, `grim`, the accessibility bus or Noctalia. Acting passes the gate first: the stop flag, the lease and the screen's lock state. Then each tool makes its own checks, such as the deny list, `expect` or a screenshot ref.

## The stop key is yours

<div class="columns wide-last">
<div class="column focused">

<Demo name="stop" call={7} label="The agent reads niri's releases in the browser. The user runs the stop command, and the agent's next click is refused with stopped." />

</div>
<div class="column">

<div class="split">

- One agent at a time holds the lease, and only the lease holder acts. Looking needs no lease.
- With [`confirm_lease`](concepts/configuration/#confirm_lease) on, you allow each lease on a desktop notification first, even when the agent's client approves tool calls without asking you. Deny, or no answer within a minute, refuses it. An agent that can run shell commands can answer the notification itself.
- A key bound to `niri-computer-use stop` cancels the running action and takes the lease back. An agent can't press it.
- An action starts only after a read of the lock state at most 250 ms old says unlocked. A lock after that read isn't caught.
- Before typing, the server checks that the window the agent names in `expect` has focus, unless it passes `"none"`. Text goes out in parts of up to 100 characters, with focus and the lock read again before each part. With the default `wtype` backend, a part that has started finishes even if focus moves, you press the stop key or the screen locks. Pointer and keyboard input is refused while an app on your deny list has focus, and element actions on its windows. A click can still land on a denied window that doesn't have focus.
- Clicks aim at a screenshot taken under the lease, at most a minute old, of an output that hasn't changed since. Windows may have moved in that time.
- Element actions refuse fields the toolkit marks as password fields; typing and clicking don't check. Clipboard copies a password manager marks as secret are withheld.
- Apps start only from presets you write. Turning on [`unrestricted`](concepts/configuration/#unrestricted) lifts that and allows niri's gated actions such as `Spawn`.
- Every action reports `accepted`, whether niri took the request, and `observed`, what niri saw afterwards. Nothing is retried.
- Calls that reach a tool go to an audit log, without the text typed, the clipboard, window titles or images.

</div>

None of this is a sandbox. A click or a key can do anything you could do, and screenshots show the agent whatever is on your screen. Read [what isn't a boundary](concepts/safety/#what-isnt-a-boundary) before you let an agent act.

## What it needs, and where it stops

<div class="columns">
<div class="column focused">

### Needs

- niri 26.04 on Linux. With another major or minor release of niri the server only looks.
- `grim`, `wtype`, `loginctl` and libxkbcommon, plus `notify-send` for `confirm_lease`.
- Rust 1.99.0 through rustup, to build it. There is no package yet.
- Claude Code, Codex, Pi or any client that starts a stdio MCP server.
- Optional: [Noctalia](concepts/noctalia/) 5.2 for its panels and lock state, and an accessibility bus (at-spi2-core) for elements.
- The server looks for `loginctl` and `noctalia` in `/usr/local/bin`, `/usr/bin`, `/bin` and `/run/current-system/sw/bin`. For a Noctalia installed elsewhere, set [`NIRI_COMPUTER_USE_DESKTOP_PATH`](concepts/configuration/#environment).

</div>
<div class="column">

### Limits

- The pointer tools need one monitor at transform `Normal`. The keyboard, screenshots and the other tools work with any monitors.
- niri 26.04 gives only floating windows a place on screen that elements can be measured from. On a tiled window, `activate_element` and `set_element_text` work; to click by element, float the window first.
- Accessibility varies by toolkit. GTK 4 works; GTK 3 and Qt apps that draw their own title bar, and Electron apps, give no element boxes.
- With the default keyboard backend, VS Code and other Electron apps ignore many shortcuts, because `wtype` sends them as other physical keys.

</div>

## Install

<div class="columns wide-first">
<div class="column focused">

From a shell inside your niri session:

<Steps>

1. Build and install the server.

   ```sh
   git clone https://github.com/ayagmar/niri-computer-use.git
   cargo install --locked --path niri-computer-use
   ```

2. Check it against your session. `niri.compat` should be `ok`, and `grim` and `wtype` `true` under `binaries`.

   ```sh
   ~/.cargo/bin/niri-computer-use status
   ```

3. Register it in your agent. For Claude Code:

   ```sh
   claude mcp add --scope user niri-computer-use -- ~/.cargo/bin/niri-computer-use serve
   ```

   [Client setup](start/clients/) covers Codex, Pi and other MCP clients.

4. Give your agents the skill, which tells them how to use the tools. From the directory you cloned:

   ```sh
   mkdir -p ~/.claude/skills ~/.agents/skills
   ln -s "$PWD/skills/niri-computer-use" ~/.claude/skills/niri-computer-use
   ln -s "$PWD/skills/niri-computer-use" ~/.agents/skills/niri-computer-use
   ```

5. Bind the stop key, inside the `binds` block of `~/.config/niri/config.kdl`, with the path `cargo install` printed:

   ```kdl
   Mod+Shift+Escape allow-inhibiting=false allow-when-locked=true hotkey-overlay-title="Stop the AI agent (niri-computer-use)" { spawn "/home/you/.cargo/bin/niri-computer-use" "stop"; }
   ```

</Steps>

Then try a [first session](start/first-session/): ask your agent to look, then to act.
