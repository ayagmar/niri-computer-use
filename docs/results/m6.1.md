## Deterministic regressions

- A01: `cargo test --locked --test protocol captures_exclude` failed before the fix with “action ran inside screenshot capture”. After the fix it passes for standalone screenshot, `screen_stable`, and a window-condition wait's final capture. Cancellation frees the mutex; a separate desk test verifies release waits for capture and observation still works without a lease. Existing action-return screenshot tests continue to pass.
- A06: `cargo test --locked -p niri-computer-use settle::tests` reproduced a 450 ms budget taking 5.15 s with a slow second capture, and a changing screen capturing at 550 ms. After the fix, the slow capture returns the prior sample unsettled at 450 ms; a slow first capture gives `deadline_exceeded` at 450 ms. A late matching frame cannot claim stability. A changing screen starts four captures at 50, 150, 250 and 350 ms within that budget. These are paused-clock correctness observations, not end-to-end performance benchmarks.
- Fractional pointer geometry: `cargo test --locked -p niri-computer-use fractional_output_motion` initially put target x=400.333333 at x=400.802324. The fixed mapping uses Smithay's ceiled pointer space, independently checked against niri v26.04 and Smithay ff5fa7df. Refs also refuse unknown or changed physical-mode geometry.
- C15: `cargo test --locked -p harness c15_accepts` failed before the harness fix. On an 853-pixel logical width, grim writes 426 pixels at scale 0.5, not the previously expected 427. PNG and JPEG now pass without changing window-position rounding or tolerances.
- Focus-based denial: protocol coverage verifies that a visible denied app does not block an allowed focused app, and `expect: "none"` does not bypass denial when the denied app actually has focus. It does not claim pointer-target enforcement.

## Limits of this evidence

- Multiple monitors, physical hotplug and additional transforms remain refused or unverified; the output-policy allowlist was not widened.
- An early headless trial with client decorations produced a fractional-height screenshot-header mismatch and failed closed. Disabling decorations gives the tested 1280×720 parent output. Arbitrary odd fractional-height capture layouts are not certified by these runs.
- GTK single-button activation and kitty scroll effects are covered. Qt, browser/Electron, hover menus and drag/drop application outcomes are not.
- Focus or stop during a running wtype stroke can still allow that stroke, up to 100 characters, to finish. Existing mid-stroke focus/submit protocol and live nested stop/crash tests pass; native keyboard equivalence was not evaluated.
- Sensitive observations remain available without a lease. Documentation now states the privacy implications; no new capability model was introduced.
- No audit-filesystem, readiness-gate, persistent-pointer, idle-resource or long-soak benchmark was run. No daemon or performance optimization was justified by these results.
- Agent evaluations were intentionally not run. The old host-contaminated M6 eval scores were not regraded. Physical input/keymap restoration, real-session lock transitions and hardware mapping still need the user present.

## Review follow-ups

Follow-up code ends at `79e2636`, after the original acceptance above. `wait_for` now serializes each capture, not the whole visual-settlement loop. Standalone and action-return screenshots retain their existing serialization. A completed first sample at or after the deadline is returned unsettled; pending captures are still cancelled. The 100 ms minimum remains a budget, not a capture guarantee, as recorded in `docs/decisions.md`. Unit and protocol fixtures share physical-mode construction without changing their rounding.

Red-first regressions:

- `cargo test --locked --test protocol unsettled_read_only_waits`: failed with an action blocked more than 500 ms by a changing-screen wait; now passes for `screen_stable` and the final screenshot after a window condition. Focus and release finish before the wait ends. Individual-capture exclusion and cancellation coverage still pass.
- `cargo test --locked -p niri-computer-use a_first_capture_completed`: both exact-deadline and late-runtime first samples failed as missing images; now return the completed frame unsettled. Existing slow-capture cancellation and 50/150/250/350 ms cadence tests pass.
- `cargo test --locked -p harness every_run_checks_c1`: failed with zero snapshot reads in headless mode; now checks before and after the complete lifecycle and reports changes even when the nested session fails. Tests use disposable fake state.

`make check` passes before and after each follow-up commit: 147 server, 114 harness and 101 protocol tests pass, one protocol test ignored; all formatting, static analysis and dependency gates pass.

Final acceptance explicitly cleared `VISIBLE` and ran sequentially. Every run reported `C1, host snapshot: unchanged`, no leftover processes and a pass. C1 reads only host metadata, never pixels, clipboard text or window titles; no input was sent to the host. Unrelated host changes can conservatively fail C1.
