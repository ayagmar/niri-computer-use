## Decisions

- **C1:** an absolute `WAYLAND_DISPLAY` works for the nested niri's winit backend.
- **C3:** no extra flip for grim images. grim's image of the nested `Flipped180` output is in displayed orientation: an image pixel is the output-local logical point times the capture scale. The output transform only enters the pointer mapping. This covers the nested `winit` output only; a real rotated monitor stays untested.
- **C5 and C6:** keep wtype: normal-use input passed, and the [Step 6 sitting](#step-6-supervised-sitting) confirmed keymap restoration after a physical key. Keep the stdin gate: no keys or modifiers arrived during the two-second hold, and closing the empty pipe released the chord. The gate does not remove the crash gap: a dying parent closes its pipe, which lets wtype continue after EOF (§11).
- **C7 and C8:** decided for the `recover` command, which doesn't exist yet: send the interrupted pointer button's release from a fresh virtual pointer, keep the manual modifier and click checks with interactive confirmation, warn that a physical ordinary key need not release wtype's synthetic keycode, and keep the input-dirty marker when recovery is uncertain ([details](#step-6-supervised-sitting)). Only Shift and left button 272 were tested physically.
- **C10:** keep the 100-character cap and three-second deadline. Twice the measured maximum is 1248.224 ms, below 3000 ms.
- **C14:** the lock source stays logind's `LockedHint`, as already settled from source. C14(a) read `no` for the unlocked session, and C14(b) was skipped.
- **C15:** grim honours `-s 0.5` on niri, so `max_width` stays a lower capture scale and the server needs no resize step. The default `format` is JPEG, because at `-s 1` it was more than 2x faster than PNG in both DP-1 runs (0.18x and 0.05x the time). The `-s 0.5` size ratio isn't needed for that. In the first run it fell just short of the rule: JPEG was 1.9998x smaller than PNG. In the second it was 4.5x smaller. The nested numbers don't count, because PNG compresses a flat colour far better than any desktop. Default `max_width` stays 1280, provisional until M1's image delivery check.
- The plan records no decision for C2, C4, C9, C12 and C13. C9 confirmed that virtual keys bypass niri binds, and C12 confirmed the scroll request order in §3.

## Other observations

- Smithay's `Transform::invert` (at `ff5fa7df`) is not the inverse of its `transform_point_in` for `Flipped90` and `Flipped270`. Every flipped transform undoes itself (`Flipped90` maps (x, y) to (y, x)), but `invert` swaps the two. The probe's first encoding used `invert`, and its unit test caught a target on `Flipped90` that niri would have put 2508.8 px away. That run's output isn't kept. The probe now inverts each transform explicitly, and all eight round-trip through the copy of niri's forward mapping within the 0.002 px tolerance.
- niri's IPC names the rotations `"90"`, `"180"` and `"270"` (`#[serde(rename)]` in niri-ipc 26.4.0), not `_90` as the Rust variants are called.
- niri passes a virtual pointer's event time through to the client: a probe motion sent with time 4001 reached `wev` as `motion: time: 4001`.
- `wev` 1.1.0 doesn't flush its output. With stdout in a file, it shows up in blocks, so the harness runs it under `stdbuf -oL`.
- grim's default scale is the output's: without `-s`, the 640x480 logical output at scale 1.5 gave a 960x720 image. So `-s 1` on a scaled output is already a downscale.

## Plan changes

Found during step 2 and applied to the plan as revision 9.

1. **§13 stage 4: niri doesn't exit when the supervisor does.** niri double-forks its `--` command and doesn't wait for it (`src/utils/spawning.rs`, `do_spawn`, at `v26.04`). The supervisor now sends `Quit` to the nested niri once its socket has been checked. niri also starts that command with stdin, stdout and stderr set to null (`spawning.rs`, `spawn_sync`), so the supervisor reports through files.
2. **§13 stage 1: the private bus socket lands in the host `/tmp`.** The default session config listens with `unix:tmpdir=/tmp`. The harness gives `dbus-run-session` its own config, which listens in `TEST_DIR/run` and has no service directories.
