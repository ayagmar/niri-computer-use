## Decisions

- **C5:** keep wtype provisionally: normal-use input passed. Keep the stdin gate: no keys or modifiers arrived during the two-second hold, and closing the empty pipe released the chord. **Unverified:** C6 keymap restoration still decides whether wtype stays in v1. The gate does not remove the crash gap: a dying parent closes its pipe, which lets wtype continue after EOF (§11).
- **C10:** keep the 100-character cap and three-second deadline. Twice the measured maximum is 1248.224 ms, below 3000 ms.

- **C3:** no extra flip for grim images. grim's image of the nested `Flipped180` output is in displayed orientation: an image pixel is the output-local logical point times the capture scale. The output transform only enters the pointer mapping. This covers the nested `winit` output only; a real rotated monitor stays untested.
- **C15:** grim honours `-s 0.5` on niri, so `max_width` stays a lower capture scale and the server needs no resize step. The default `format` is JPEG, because at `-s 1` it was more than 2x faster than PNG in both DP-1 runs (0.18x and 0.05x the time). The `-s 0.5` size ratio isn't needed for that. In the first run it fell just short of the rule: JPEG was 1.9998x smaller than PNG. In the second it was 4.5x smaller. The nested numbers don't count, because PNG compresses a flat colour far better than any desktop. Default `max_width` stays 1280, provisional until M1's image delivery check.

## Other observations

- Smithay's `Transform::invert` (at `ff5fa7df`) is not the inverse of its `transform_point_in` for `Flipped90` and `Flipped270`. Every flipped transform undoes itself (`Flipped90` maps (x, y) to (y, x)), but `invert` swaps the two. The probe's first encoding used `invert`, and its unit test caught a target on `Flipped90` that niri would have put 2508.8 px away. That run's output isn't kept. The probe now inverts each transform explicitly, and all eight round-trip through the copy of niri's forward mapping within the 0.002 px tolerance.
- niri's IPC names the rotations `"90"`, `"180"` and `"270"` (`#[serde(rename)]` in niri-ipc 26.4.0), not `_90` as the Rust variants are called.
- niri passes a virtual pointer's event time through to the client: a probe motion sent with time 4001 reached `wev` as `motion: time: 4001`.
- `wev` 1.1.0 doesn't flush its output. With stdout in a file, it shows up in blocks, so the harness runs it under `stdbuf -oL`.
- grim's default scale is the output's: without `-s`, the 640x480 logical output at scale 1.5 gave a 960x720 image. So `-s 1` on a scaled output is already a downscale.

## Plan changes

Found during step 2 and applied to the plan as revision 9.

1. **§13 stage 4: niri doesn't exit when the supervisor does.** niri double-forks its `--` command and doesn't wait for it (`src/utils/spawning.rs`, `do_spawn`, at `v26.04`). The supervisor now sends `Quit` to the nested niri once its socket has been checked. niri also starts that command with stdin, stdout and stderr set to null (`spawning.rs`, `spawn_sync`), so the supervisor reports through files.
2. **§13 stage 1: the private bus socket lands in the host `/tmp`.** The default session config listens with `unix:tmpdir=/tmp`. The harness gives `dbus-run-session` its own config, which listens in `TEST_DIR/run` and has no service directories. This is also what makes the kickoff's "`DBUS_SESSION_BUS_ADDRESS` points into `TEST_DIR`" check possible.
3. **§13 stage 0: the containment rule and the kept variables contradict each other.** "Every path variable must resolve under `TEST_DIR`" can't hold for `HOME` and `PATH`, which the same stage keeps. The harness applies containment to the XDG and Noctalia directories, exempts `WAYLAND_DISPLAY`, keeps `HOME`, `PATH` and `LANG` as they are, and rejects any other variable.

Found during step 3 and applied to the plan as revision 10.

4. **§8 mapping step 3: say which inverse.** "Inverse output transform" has to be the inverse of Smithay's `transform_point_in`, not `Transform::invert`, which is wrong for `Flipped90` and `Flipped270` (see above). The eight-transform unit test in §8 catches it.
5. **§8, last bullet, and §3: what grim does is now observed.** grim's image of the nested `Flipped180` output is in displayed orientation, so "Review says it is likely; not yet observed" can become verified for `winit`. grim's default scale is the output's, which §8's `s = min(output scale, …)` already assumes.
6. **§6 `scroll` row: wrong order, and the value is known.** The row says `axis_source(wheel)` → `axis_discrete(…)` → `frame`, which niri ignores the source for, because `axis_source` only changes a frame that `axis_discrete` has created (§3, C12). It should be `axis_discrete(axis, 15 × notches, notches)` → `axis_source(wheel)` → `frame`, and the per-notch value is 15 from niri's source, no longer unverified.
7. **§13 harness: details the plan doesn't have.**
   - `harness supervise` takes a fourth argument, the path of the `vpointer` probe.
   - Test steps start processes through the supervisor's session, which checks the nested endpoints before each one. A background process such as `wev` has a watchdog that kills it at its deadline.
   - `wait_until` polls every 50 ms and ignores a result that arrives after its deadline.
   - `wev` runs under `stdbuf -oL`, and checks match `wev` events by the event time each probe call sends.
   - C15 on DP-1 is `harness host-capture`, run from the user's shell, because the supervisor only reaches the nested niri.
8. **§14 C15: decide on a real output.** The nested output is mostly flat colour, so only real-output numbers decide `format`, and they depend on what's on screen. Downscaling in grim is not free: on DP-1, JPEG at `-s 0.5` took about 95 ms against 13 ms at `-s 1`, so `max_width` trades capture time for image size.

Found during Step 4; not applied to the plan.

9. **§13 harness: keyboard observations need different helpers.** Keyboard checks match calls by offsets in wev's log, since wtype sends key time 0 (`main.c`, `type_keycode`, lines 345–357). They parse complete key and modifier records with continuation lines (`wev.c`, lines 383–435). `Session::start_with_stdin` and `Process::feed` hold or write and close stdin within the child's deadline, so no gate probe is needed. `still_absent` checks for the full interval and at its end; it is used for the two-second C5(b) hold and one-second C9 negative check. **Verified:** source and both runs above.

**Unverified:** C6, C7, C8, C9's physical positive control and C13 are outside Step 4 and have no results here.
