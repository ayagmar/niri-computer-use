## Other observations

- **The stop key on the real session.** The bind `Mod+Shift+Escape … { spawn "/home/ayagmar/.cargo/bin/niri-computer-use" "stop"; }` was added through chezmoi; `niri validate` passed and niri reloaded the config. `niri msg action spawn -- ~/.cargo/bin/niri-computer-use stop` created `$XDG_RUNTIME_DIR/niri-computer-use/niri.wayland-1.1487/stop`, `status` reported `stop: true`, and `resume` cleared it. The key itself wasn't pressed.
- **The lock state follows niri's session.** On this machine `XDG_SESSION_ID=3` is a `tty` session and niri runs as a systemd user service. niri sets `LockedHint` on its own `XDG_SESSION_ID`, so the server asks logind about the session in niri's environment, found through the socket's peer credentials. With the screen locked, logind's hint for session 3 was `yes` and Noctalia's `locked` was `true`; `status` reported `locked` from `logind`.
- **Refusals.** The protocol tests check every refusal over stdio: `lease_held`, `stopped`, `recovery_required` with the marker's operation and phase, `read_only` for an invalid policy file, and `screen_locked` for a locked screen and for an unknown lock state.
- **Removing the runtime directory.** A review reproduced two holders after `rm -rf` of the runtime directory under a holder. The kernel delays a directory's deletion event while a file in it is open, so the server checks the directory's and the lease file's inodes on every event and once a second; the holder now gives the lease up and the server refuses it until restart.
