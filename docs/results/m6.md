Nested runs keep their files in `target/e2e/<run>/` and eval results in `target/skill-evals/`, neither committed.

Machine: niri 26.04 (8ed0da4), Noctalia 5.2.1, Rust 1.99.0, Claude Code's `claude -p` with the models `sonnet`, `haiku` and `opus`.

No input was sent to the real session: every agent ran inside the nested niri, with only the nested server (`--strict-mcp-config`), no shell (`--tools=Skill,Read`) and only project settings.

Iteration 3 has `screenshot: true` on actions, `submit` on `type_text`, `keys` lists, `wait_for` and `restore_focus`. Iteration 2 had 1 run per scenario, iteration 3 has 2.

## Other observations

- **Host keys reached the nested window.** Three Haiku failures were keys the agent never sent: the audit log shows one `type_text` with `submit`, and wev then logged `Super_L` and `Shift_L` after the Enter, or before the first F1. They came from the host keyboard while the floating nested window had focus. A nested niri that isn't on screen would avoid this.
- **Calls sent together.** The grader now reads the transcript: one Haiku run without the skill sent two `key` calls in one turn, which the audit log alone shows as two calls one after the other.
- **The dialog scenario.** With `submit`, Sonnet sent the message in one call before a dialog opened 1.5 seconds after the lease, so the dialog now opens as soon as the lease is taken. When it opened first, agents got `focus_mismatch`, focused wev again and sent the whole message; some didn't name the dialog in their answer.
- **Opus.** The Opus runs were stopped before they finished, to save quota.
- **wev draws nothing.** Agents described wev's window as a checkerboard in screenshots; the grading reads wev's log, not its pixels.
