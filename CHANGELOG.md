# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Unreleased

### Upgrading

- Before upgrading, end every running `niri-computer-use` process, servers, bridges and shared engines alike, then start your clients again. `pgrep -a '^niri-computer-u'` lists them. Older builds keep their runtime directory under `XDG_RUNTIME_DIR` rather than beside niri's socket, so an old and a new server on one niri share neither the lease nor the stop flag, and they don't take the input-dirty marker's lock.

### Security

- `clipboard_read` no longer returns what the clipboard's owner marked `x-kde-passwordManagerHint: secret`, such as a password copied from KeePassXC, or text a `paste` left behind: `text` is null with the new reason `secret`, and the text is never read. The hint and the text come from the same copy, read over data-control in the server rather than with `wl-paste`.
- `clipboard_read` needs the lease and returns only what was copied while it was held, such as a link an app's "Copy link" button put there: what you copied before `acquire_desktop` is withheld with the new reason `copied_before_lease`, and never read. Without the lease it refuses with `lease_required`. `make inspect-check` now expects that refusal.

### Added

- `screenshot` zooms in: with target `region` and an earlier screenshot's `screenshot_ref`, `region` is read in that image's pixels and captured from the same output at its own scale, with no width limit unless `max_width` is given, so an agent can read small text without a full-resolution screenshot of the whole output. It works without the lease and in the `observe` profile: screenshots taken without the lease now get a `screenshot_ref` too, which only a zoom by the same session takes.
- `confirm_lease = true` in the policy file, or `NIRI_COMPUTER_USE_CONFIRM_LEASE=1` for one client: `acquire_desktop` waits for you to choose Allow on a desktop notification, shown with `notify-send`, before the lease is granted, even when the client approves tool calls on its own. Deny, a dismissed notification or no answer within 60 seconds fails with the new error `lease_declined`. Off by default. `status.confirm_lease` reports it, and `status.binaries` whether `notify-send` is found. While you haven't answered, `status.lease.holder` has `pending: true`.
- Optional GTK 4 button-activation acceptance in `make nested-input`: 100 actual activations with observed-counter latency percentiles.

- `niri-computer-use serve`: an MCP server over stdio with two read-only tools, `status` and `outputs`.
- `niri-computer-use status`: prints the same readiness report as the `status` tool.
- `screenshot` tool: one output or a region inside one output, through grim, as JPEG or PNG with its geometry and scale.
- `clipboard_read` tool: the clipboard's text.
- An audit log of every tool call at `$XDG_STATE_HOME/niri-computer-use/audit.jsonl`, with argument metadata and outcomes but no contents. `status` reports its path and last write error.
- `shell_status` tool, present when Noctalia is installed. `status` reports whether Noctalia is running and the lock state from logind and Noctalia; the screen counts as locked if either says so. logind is asked about the session niri itself runs in, read from niri's environment, so the answer doesn't depend on where the server was started, and only when niri runs as `niri --session`, the only niri that sets logind's hint.
- `desktop_state` tool: windows, workspaces, focus, overview and keyboard layouts from niri's event stream. `status` reports whether the stream is connected.
- The `niri-computer-use` skill in `skills/`, for agents using the read-only tools.
- `make inspect` and `make inspect-check`: the server under the pinned MCP Inspector.
- `niri-computer-use stop` and `resume`: set and clear a stop flag in the niri instance's runtime directory, `niri-computer-use/<instance>/` beside niri's socket. `status` reports it as `stop`.
- `acquire_desktop` and `release_desktop`: one server at a time holds the lease on a niri instance, an exclusive `flock` in the runtime directory. The stop flag takes it back. `status` reports the holder. New error names `lease_held`, `stopped` and `recovery_required`.
- The policy file, `$XDG_CONFIG_HOME/niri-computer-use/policy.toml`: launch presets and an app deny list, checked at startup and reported by `status`. `acquire_desktop` refuses with `read_only` while it is invalid or niri's version isn't supported, and with `screen_locked` while the screen is locked or its lock state is unknown.
- The `niri-computer-use` skill covers the lease tools and tells agents to leave stops, recovery and locks to the user.
- `make nested-control`: M2's acceptance in a nested niri, with the nested Noctalia as the lock source.
- `make nested-actions`: M3's acceptance in a nested niri: launch, reuse, focus, close and `interrupted`, against fixture windows the harness provides.
- `focus_window`, `focus_workspace`, `launch` and `close_window`: the first tools that act on the desktop, through niri's IPC. They require the lease and check the stop flag, the input-dirty marker and the lock state before each action, the lock state again once the rest of the readiness report is read, the flag and the marker after that, and a stop cancels a running one; once the request went out, a stop or a lost lease makes the outcome `uncertain`, with `accepted: true` if niri had answered, and no screenshot. Each result says whether niri `accepted` the action and what was `observed` on niri's event stream: `focused`, `closed`, `pending`, `one`, `ambiguous`, `none`, `timeout`, `interrupted` when someone else moved focus, or `uncertain` when niri's reply was lost. `launch` only starts presets from the policy file, and with `reuse` focuses an existing window. An outcome in doubt comes with a fresh screenshot of the focused output. New error names `lease_required` and `unknown_preset`. The audit log records `accepted` and `observed` for these tools.
- `status.policy.preset_names`: the names `launch` takes.
- `niri-computer-use recover`: clears the input-dirty marker after ending the input child it names and asking the human to confirm that no input is held. `status` reports the marker as `input_dirty`.
- `shell_open` and `shell_close`, present when Noctalia is installed: open or close the Noctalia panels `control-center`, `wallpaper` and `tray-drawer`, then poll Noctalia's `activePanelId` every 100 ms for up to two seconds, reporting `opened`, `closed`, `timeout` or `uncertain`. Every other panel is refused with the new error name `panel_not_allowed`. They need the lease and pass the same gate as the other actions.
- `make nested-eval`: runs an agent (`claude -p`) with a skill against one scenario in a nested niri and grades it from the audit log.
- `screenshot: true` on every action: the result comes with a screenshot taken once the screen stopped changing, with `settled` in its metadata.
- `wait_for` tool: waits until a window appears, closes or changes its title, or the screen stops changing.
- `type_text`'s `submit`: presses Enter only once all of the text went out, and reports `submitted`.
- `acquire_desktop` returns `users_window`, and `release_desktop` takes `restore_focus` to give focus back to it.
- `make nested-eval` scenarios `dialog-midway` and `errand`, a check for calls sent together, and call and turn counts in `timing.json`.
- `pointer_move`, `click`, `drag` and `scroll`: input through niri's virtual pointer, aimed at pixels of a screenshot this lease took through its `screenshot_ref`. A ref expires after 60 seconds or when its output changes. They run only on one enabled output at transform `Normal`, and refuse others with `untested_output_config`.
- `key` and `type_text`: keyboard input through `wtype`, into the window named in `expect`, refused with `focus_mismatch` elsewhere and with `app_denied` for an app on the policy's deny list.
- An input-dirty marker written before input and removed once it is released, so a crash mid-input leaves `recovery_required` until `recover`.
- An experimental native keyboard backend, `NIRI_COMPUTER_USE_KEYBOARD=native`: niri's virtual keyboard protocol with focus checked before every key, symbols the layout lacks typed through a temporary keymap that is proved restored, and modifiers held through `click`, `drag` and `scroll` with `keys`. `wtype` stays the default.
- A crash guardian for each server: when the server dies holding native keys or pointer buttons, it releases them at once. The marker still waits for `recover`.
- When a server and its crash guardian die together, the next server or engine to start on that niri sends the releases the dead server's marker names. The marker still waits for `recover`.
- `paste`: up to 1 MiB through the clipboard, with a keeper process that saves every type the clipboard offers, holds the text marked as a secret for clipboard managers, and puts the saved clipboard back, unless the server dies once the key may be on its way, when it keeps the pasted text and reports `clipboard: kept`. It refuses with `clipboard_unsaved` before changing anything when it can't save the clipboard, the clipboard is marked secret, or something else is copied while it saves.
- `screenshot`'s `save_path`: a full-resolution PNG under the capture directory, created new, never through a symlink. The directory is the policy file's `capture_dir`, or `~/Pictures/niri-computer-use` in the session's home without one, created with mode `0700`; `capture_dir = ""` turns saving off, refused with `save_not_enabled`. `status.policy` shows the directory in use as `capture_dir`, and `capture_dir_source` says whether it is the policy's or the default.
- `elements`: one window's accessible elements over AT-SPI, with roles, names, states, actions and boxes in layout coordinates, listed when the session has an accessibility bus. Each element has an `element_ref` under the lease that `pointer_move`, `click` and `drag` take as `element`; it is checked again before aiming. New error names `not_accessible`, `ambiguous_window`, `element_stale` and `element_unmappable`. A window's accessible frame is found by its size and title; a frame of the window's size with another window's title is `ambiguous_window`, never taken. Frames are decided for all of the app's windows together: a frame that another window of the app could be as well, because no other frame has that window's size and the titles don't tell the two apart (the same title, as two "Untitled" documents have, or one of them unknown), is `ambiguous_window` too.
- Session discovery: `XDG_RUNTIME_DIR`, `NIRI_SOCKET` and `WAYLAND_DISPLAY` are found when the client doesn't pass them, from the user's only running niri, so clients need no environment settings. Given variables win, and discovery never chooses between niri instances.
- `niri_action`: any niri action in niri's IPC JSON, such as fullscreen, floating or a window's width, with the window's state as niri reports it after. Actions that run programs, write files or reach past the layout are refused with `unrestricted_required`.
- `unrestricted = true` in the policy file, or `NIRI_COMPUTER_USE_UNRESTRICTED=1` for one client: lets `niri_action` send the gated actions, lists the `noctalia` tool, and lifts the preset rules. Off by default. `status.unrestricted` reports it.
- `noctalia`: any Noctalia command, as `noctalia msg` sends it, listed only with Noctalia installed and `unrestricted` on.
- A shared engine per niri instance, on by default (`shared = false`, or `NIRI_COMPUTER_USE_SHARED=0` for one client, turns it off): each client's `serve` relays to one `niri-computer-use engine`, which holds one desk, guardian, event stream and accessibility connection for every client, while policy, `unrestricted`, keyboard backend, home and the `PATH` and working directory that `grim` and `wtype` run with stay per client.
- The documentation site, with `llms.txt` and a Markdown address for every page.
- `niri-computer-use --version`.
- `elements` returns one line per element as its text, `element_ref role "name" [states] ("action" …) x,y,w,h`, and lists only elements with an action or editable text by default. `interactive_only: false` lists labels too, and `format: "json"` gives the full objects as text; `structuredContent` always has them.
- Every tool has a `title` and `openWorldHint: false`. `status`, `desktop_state` and `screenshot` carry `_meta["anthropic/alwaysLoad"]: true`, so Claude Code loads them without a tool search.
- Tool profiles: `tools = "observe"`, `"act"` or `"full"` in the policy file, or `NIRI_COMPUTER_USE_TOOLS` for one client. `observe` lists only `status`, `desktop_state`, `screenshot`, `elements` and `wait_for`; `act` leaves out `niri_action`, `noctalia` and `shell_panel`. The default, `full`, lists every tool as before. `status.tools` reports the profile.
- `elements` marks an element whose ref nothing on the accessibility bus binds to the record it acts on: `unbound` in its JSON, `unnamed_row` or `repeated`, and `unbound:<why>` at the end of its line. Every tool taking an `element` refuses such a ref with the new error `element_unbound`, whose detail says to aim the pointer tools at its pixels.

- `status.engine` reports the serving process's `version`, the file it was started from (`exe`), whether that file has been replaced since (`replaced`, as after a reinstall), and its `cgroup`.
- A bridge starts the shared engine through `systemd-run --user --scope`, so the engine has a scope of its own and stopping the scope of the client that started it no longer ends it for every client. Without systemd, or when the manager refuses, the engine starts as before, and `status.engine.unscoped` says why it has no scope of its own. A `systemd-run` that hangs is killed after two seconds.

### Changed

- Elements of a tiled window report `unmappable: tiled`, and a pointer tool aimed at one fails with `element_unmappable` and a detail starting `tiled:`, where both said `not_showing`. niri 26.04 gives only floating windows a place on screen, so the element is there but can't be placed. `not_showing` now means only an element that isn't showing or a floating window with no place, as on a workspace that isn't shown.
- The audit log's `activate_element` and `set_element_text` entries have `gate` once the last check ran: how long each pass took and how old its answers were when the call went out, in milliseconds.
- wl-clipboard is no longer needed at run time: nothing the server runs uses `wl-paste` any more, and `status.binaries` no longer lists it.

- Automatic nested suites run inside isolated headless cage by default, without host snapshots. `VISIBLE=1` or `--visible` keeps the human path; sittings remain visible.
- Safety documentation explicitly distinguishes focus-based app denial from pointer-target isolation, and sensitive read-only observations from private data.

- `key` takes `keys`, a list of up to 16 combinations pressed in order, instead of one `combo`, and stops with `interrupted` and a `pressed` count if focus moves.
- `release_desktop` requires `restore_focus`.
- `type_text` takes up to 1000 characters and types them in parts of 100, stopping with `interrupted` and a `typed` count if focus moves between parts.
- `screenshot` waits for a running action of the same server before capturing.
- The tool descriptions and the server's instructions carry the rules agents most often broke: no screenshot alongside an action, no Enter after text that didn't fully go out, apps only through presets, focus back to the user's window when done.
- The `niri-computer-use` skill is rewritten: a description that says when to load it, a shorter workflow with reasons and examples, and the tool and error tables moved to `references/`.
- The project is renamed from `niri-desktop-mcp` to `niri-computer-use`, including the binary, the MCP server's name and the audit log's directory.
- `niri_action`'s `DoScreenTransition` needs `unrestricted`: it can freeze every output and screencast for up to 65 seconds.
- A preset may no longer start `tmux`, `screen`, `bwrap`, `firejail`, `unshare`, `chroot`, `ssh`, `flatpak-spawn`, `nix`, `nix-shell`, `strace`, `gdb`, `script`, `docker` or `podman` unless `unrestricted` is on: each runs whatever command follows it.
- `activate_element` and `set_element_text`, listed with `elements`: an element's own action, or its whole text replaced, through the accessibility bus instead of the pointer or keyboard. They need the lease and pass the same gate as the other actions; the element's window must have keyboard focus and `expect` must name it, and the deny list applies to it. `activate_element` reports what it saw 300 ms later (`present` with the states that changed, `gone` or `unknown`), `set_element_text` whether the field holds as many characters as were set (`matched`, `differs` or `unknown`); a reply lost after the call went out is `uncertain` with `accepted: null`, as is a stop or a lost lease once the call went out, then with no screenshot, and with `accepted: true` when the app had already answered. `focused_window` is the focus when the change report ended, after a lost reply too; niri's event stream lost meanwhile makes the outcome `uncertain` with no focused window and the loss in `detail`, with `accepted: true`, or `null` when the reply was lost as well. Right before the call that acts, the element, its action or editable text, its states and its role are read again, one at a time, and only then the focus, `expect`, the deny list, the lock screen (read again after the rest of the readiness report), the stop flag, the input-dirty marker and the lease. Every answer the call relies on was read within 250 ms of the call going out: checks that take longer are done once more, and a second slow pass is the new error `element_busy`, with nothing sent. A change inside those 250 ms can be missed. The element and the elements it sits in must still have the names and places they were listed with, so a button its own activation relabelled is `element_stale`, and the agent lists again. In GTK 4's list view a ref to a row's button is stale once a record above it was removed or the list scrolled; a row reused in place for another record is caught only where the row or an element around the button is named after its record, which GTK 4's rows aren't. Fields the toolkit marks as passwords (role `password_text`) are refused by both with the new error name `secret_field`; a GTK 4 entry that only hides its text isn't marked and isn't refused. Text over 64 KiB is refused with `text_too_long`. The audit log keeps the role, the action's kind and index and the text's length, never names, action names or text. Their failures, and a pointer aim's at an element, leave out the app's D-Bus error messages and name only standard D-Bus errors, any other as `application_error`.
- Every action result says what niri saw it change, as `changes`: windows opened and closed, focus and the focused workspace from and to, and windows whose title, app id, workspace, floating, size or urgency changed. It covers the action until niri has reported no change it would show for 250 ms, counted from the start of the action, so an event such as niri setting a window's focus timestamp doesn't extend it, at most half a second after the action's own wait, or the settled screenshot when one was asked for, and is left out when nothing changed. `focus` ends it once its own wait ended with `focused` or `closed` and niri's events from that refresh are in, at most 50 ms later; `niri_action` once its own wait ended with `changed` or `closed`, a fixed 200 ms after the first change, or with `unchanged`, after a second without one; and `Spawn` and `SpawnSh` at once, since their window comes later and `wait_for` finds it; a `niri_action` that is only `sent` waits as the others do. `focused_window`, and `niri_action`'s `window`, come from the view the report ends at, so a result names one focused window. When niri's event stream ends during the report, or can't be watched at all, `changes.lost` says why. With the new `element_changes` on `click` (with `element`), `activate_element`, `set_element_text`, `key`, `type_text` and `paste`, it also lists the accessible elements of the element's or the focused window that were added, removed or changed, from a walk before and after, with fresh element refs, or `unknown` with why. The audit log keeps only counts of it. The skill and the server instructions tell agents to read `changes` before taking a screenshot.
- `elements` returns what it read, with `capped_reason: budget_exhausted`, when a large tree runs out of its three seconds, instead of failing with `deadline_exceeded`; `role`, `name_contains` and `limit` stop the walk early.
- With `unrestricted` on and no preset for an app, the skill and the tool text have agents start it with `niri_action`'s `Spawn` and wait for its window, instead of asking for a preset.
- The runtime directory that holds the lease, the stop flag and the input-dirty marker is `niri-computer-use/<instance>/` beside niri's socket with every symlink resolved, no longer under `XDG_RUNTIME_DIR`. A socket that doesn't resolve to the user's own leaves the server with no runtime directory rather than one picked another way.
- `stop` and `resume` find niri's socket without connecting to it, so the stop key works while niri hangs.
- A client that stops reading its server's output loses its session and the lease: once 32 lines wait for it, or one has waited 30 seconds, the bridge exits. So does a client that sends more than 32 MiB the shared engine hasn't taken yet, so its closed stdin can't go unseen behind that input.
- Shorter tool descriptions and schemas, with no change in behaviour: the input schemas drop `$schema`, field text no longer repeats defaults and ranges the schema states, and the long descriptions keep their refusals and rules while the mechanics live in the docs.
- `focus_window` and `focus_workspace` are one tool, `focus`, which takes `window_id` or `workspace_id`.
- `shell_open` and `shell_close` are one tool, `shell_panel`, which takes the panel and `open: true` or `false`.
- `outputs` and `shell_status` are gone: `desktop_state` has `outputs`, each with its name, make, model and `logical` position, size, scale and transform, and with Noctalia installed `shell`, Noctalia's status or `noctalia_unavailable`.
- `paste` is gone: `type_text` takes `via: "paste"` with `paste_keys` (`ctrl+v`, `ctrl+shift+v` or `shift+Insert`) to paste up to 1 MiB through the clipboard, with the same results. `submit` with a paste is an argument mistake.

### Fixed

- An element of a floating window on a workspace that isn't shown no longer gets a box, and a pointer tool aimed at its ref, even one listed while the workspace was shown, fails with `element_unmappable` (`not_showing`) and sends nothing. niri reports a floating window's place on inactive workspaces too, so the box pointed at the shown workspace's window there, and a click through the ref landed on it.
- While niri's overview is open, elements have no box (`not_showing`) and a pointer tool aimed at an element ref fails with `element_unmappable` and sends nothing. The overview zooms the workspaces out, but niri reports a floating window's place as it was, so the box pointed elsewhere.
- When niri's `Workspaces` or `Outputs` request fails, `elements` and a pointer tool aimed at an element ref fail with `upstream_error` and niri's message. Both used to carry on as if the window weren't shown, so a tiled window's elements said `not_showing` rather than `tiled`.
- `loginctl` and `noctalia` are looked for in the system's directories, `/usr/local/bin:/usr/bin:/bin:/run/current-system/sw/bin`, or in those `NIRI_COMPUTER_USE_DESKTOP_PATH` names, rather than on `PATH`. A shared engine started by a client with a narrow `PATH` used to leave the lock state to Noctalia alone and hide Noctalia's tools for every client. `status.desktop_programs` reports where they were found, and `status.binaries` no longer lists `loginctl`. A Noctalia installed per user, such as in a Nix profile or `~/.local/bin`, needs that variable, set the same for every client; a trailing slash or a repeated directory in it makes no difference.
- A `wtype` stroke is let past its gate only while the server's last read of the lock state is under 250 ms old, checked again right where the gate opens. The task that opens it can run after the action's own check, for example while a shared engine serves another client, and could send the stroke on an older read.
- A `key` or `type_text` call whose first stroke or native key failed after it may have gone out says so, `pressed 0 of 1 keys, and more may have gone out`, instead of returning the bare error. Every keyboard failure with such a count carries `may_have_sent: true`, which the audit log keeps.
- `acquire_desktop` binds its clipboard watcher before granting the lease, so a call cancelled meanwhile leaves no lease, rather than a lease whose `clipboard_read` failed with `upstream_error` until it was taken again. A stop or the session's end during the bind refuses the call, and a release waits for it. A late watcher no longer replaces the one of the session that took the lease next, and a second `acquire_desktop` of the holder keeps the watcher it has, which before was replaced and withheld text copied during the lease as `copied_before_lease`.
- `noctalia` refuses an argument holding U+001E or a line break as an argument mistake. Noctalia reads U+001E as the end of its message's working directory, so one inside an argument rewrote the command.
- `niri_action` with a null window id goes out naming the window focused at the check, for every action, as `CloseWindow` already did; with no window focused it is an argument mistake. Focus moving before niri handled it made the action act on another window.
- A slow lock read no longer looks like a locked screen. Noctalia and logind are asked side by side, in the readiness report and in the read every action makes after it, so a slow source no longer adds its time to the other's. A call that still can't go out within 250 ms of the read gets the new error `lock_stale`, which an agent can retry, instead of `screen_locked`, which told it to stop on an unlocked screen.
- `type_text` refuses typed text holding a control character as an argument mistake. Both backends pressed a line break or a tab as Return and Tab, so a message went out before the rest of it while the result said `submitted: true`, and others as BackSpace, Clear, Escape or Delete. Use `submit`, `key`, or `via: "paste"` for text with several lines.
- A stop or a lost lease once `key` or `type_text` started typing, or once `shell_panel` or `noctalia` sent its command, ends the call `uncertain` with the reason in `detail`, as for the niri and element actions, instead of `stopped` or `lease_required`: the input or the command may have taken effect. `typed` and `pressed` count what `wtype` finished. A paste and the pointer tools still return the error.
- `type_text` stops before its next part when the focused app goes on the deny list during the call, with `app_denied` saying how much was typed, and refuses with `focus_mismatch` when focus moves before anything was typed.
- `shell_panel` no longer sends its command when the input-dirty marker or the stop flag was set while they read Noctalia's open panel.
- Input that finds another input's marker set when it writes its own refuses with `recovery_required`, as an action does, instead of `upstream_error`.
- Every acting tool sends its request, input or command within 250 ms of when its last read of the lock state began, and reads the lock state again first when that read is older. A read asks Noctalia and then logind, so a lock that came while logind's answer was on its way let `focus`, `key` and the other niri, input and Noctalia tools act after the screen locked. A call that can't go out within 250 ms of a read is refused with `lock_stale`, and so is a paste's key that the clipboard keeper admits too late for that bound; the clipboard is then put back. A `type_text` call refused after its text went out says whether the submitting `Return` was pressed, or may have been when `wtype` failed after starting on it, instead of `typed 150 of 150 characters before this: … nothing was sent`.
- A ref to a control in a list's row was accepted after the list reused the row in place for another record, as Qt Quick's list view does, so `activate_element`, `click` and the other tools taking an `element` acted on a row that no longer showed the record it was listed with. A ref is now bound to its record only by a named row on the accessibility bus, a `list_item`, `table_row` or `tree_item` whose name changes with its record. A control in an unnamed row, or outside any row while `elements` read other objects of its role and name, listed or not, is refused with `element_unbound`. Where a toolkit puts rows on the bus without a row role, as Qt Quick does for most of a list, a lone reused row, or one whose look-alike elements `elements` didn't reach, still isn't caught: aim the pointer tools at a list record's pixels.
- Standalone screenshots and `wait_for` capture sequences hold the action mutex throughout capture, excluding subsequent server actions and lease changes.
- Settled capture budgets include the initial delay and capture work. A timed-out later capture returns the last completed sample unsettled; no completed sample gives `deadline_exceeded`.
- Fractional-scale pointer motion uses niri's ceiled physical-mode space rather than truncated IPC dimensions. Unknown or changed pointer geometry refuses input.
- C15's nested capture assertions use grim's truncated image size instead of rounding odd dimensions.
- `close_window` and `niri_action`'s `CloseWindow` refuse with `app_denied` to close a window whose app is on the policy's deny list, named or focused.
- The audit log no longer keeps text an agent passes to `niri_action` or `noctalia`, such as a `Spawn` command or a notification body: it logs the action's name, field names, numbers and booleans with every string as its length in bytes, and only Noctalia's argument count and byte lengths.
- The audit log no longer keeps other strings an agent chose as given. Key combinations, presets, Noctalia panels, roles and refs are written only when the server knows them, and otherwise as a category and their length; `key` no longer writes combinations it then refuses. An `expect` app id is written as its length and whether focus matched it, `wait_for`'s app id as its length, a screenshot's target as its kind, never an output's name, and its save path as its length.
- Another session's `acquire_desktop` refuses with `lease_held` at once, instead of waiting for the owner's running action. After its readiness check it looks again at whether the session has ended, the stop flag and the input-dirty marker before granting the lease.
- A stopped, cancelled or disconnected `paste` no longer restores the clipboard before a key already on its way arrives. If the server dies once the key may be on its way, the keeper keeps the pasted text and reports `clipboard: kept` rather than risk pasting the saved clipboard.
- `paste` sends its key only once the keeper has answered that it still holds the text. A server delayed past the keeper's ten-second wait could paste the user's restored clipboard instead; now the call fails, says nothing was pasted, and the clipboard stays restored.
- A copy made while `paste`'s keeper saves the clipboard refuses the paste with `clipboard_unsaved`, instead of being lost to the restore of the older one.
- Servers for one niri share its lease and stop flag whatever `XDG_RUNTIME_DIR` or `NIRI_SOCKET` spelling their clients pass. A socket with a hard link, which would have split them, gets no lease by any name, and `status` says why under `lease.error`.
- A shared-mode client that reads its output keeps its session when the engine is lost with more than 32 requests in flight, and each gets `engine_lost`; before, the bridge took the burst of answers for a client that had stopped reading and exited.
- Every change to the input-dirty marker takes one lock, so an older call's cleanup can't remove a newer call's marker.
- A marker left by a cleanup that failed, such as a `wtype` killed by a signal, now sends the user to `recover` instead of saying the input is still finishing; that answer is kept for input the server is still finishing. A marker another server wrote says its input may still be finishing and to try again in a few seconds before `recover`, while that server runs and its crash guardian hasn't sent the releases.
- The native keyboard restores the compositor's latest keymap, not the map from the start of the call, whether or not the call extended it, with zero modifiers in the layout niri has active: at the end of a call, after a cancelled one, and from the crash guardian and `recover`, which used the layout the marker recorded at the call's start. If niri doesn't answer, a call uses the layout niri last reported to it, and the guardian and `recover` the marker's, saying so.
- The 16 MiB line limit applies to every line a read ends, not only the last.
- An input cleanup that outlives its call, such as a dropped native `paste`'s release, ends within ten seconds of its start, as long as the server waits for it at exit. One still running then keeps its marker for `recover`, and a call waiting for it says so.
- Modifiers held with `keys` on a native `click`, `drag` or `scroll` end as native typing does: the compositor's latest keymap in the layout niri has active, proved before the marker comes off. They used to restore the map and layout from the gesture's start.
- A `paste` after a `clipboard: kept` outcome replaces the kept text instead of refusing with `clipboard_unsaved`, and clears the clipboard afterwards rather than put that text back. The keeper marks its text with `application/x-niri-computer-use-paste`.
- `paste` waits up to eleven seconds for the keeper to take the clipboard, as long as the keeper's steps can take, instead of five.
- `paste` waits six and a half seconds for the keeper's last report, as long as its wait for a read and its two round trips can take, instead of five, so a slow niri no longer turns a finished restore into `clipboard: unknown`.
- A native typing call gets 50 ms for each character or key, and at least three seconds; past that it stops with `deadline_exceeded` saying how much it typed. Each round trip had a deadline, but a niri that answered every one late, as a nested niri waiting for its parent's frames does, could stretch a call without end.
