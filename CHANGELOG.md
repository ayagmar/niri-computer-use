# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Unreleased

### Added

- The Chromium and Electron section of the elements page, and the troubleshooting page, say how to start those apps with accessibility on, so `elements` works on them.
- A bug report template that asks for the niri version, `status` output, the agent and model, and the error name and `detail`.

### Changed

- The skill and the server's instructions tell agents to load the tool schemas before the first call in Claude Code, that `submitted: true` means Enter went out and a late-drawn message is not a reason to send it again, to take a screenshot before typing after `ctrl+t` or a closed file picker, to hand the desktop back on a `focus_mismatch` that names their own terminal, and to tell you once that restarting a Chromium or Electron app enables element tools.
- The README opens its Safety section with a six-row table and no longer shows a harness run as its example. The home page says the audit log records every call that reaches a tool.
- crates.io links the project site as `homepage` and `documentation`.
- A tool given a field it doesn't take now fails naming that field and the ones it expects, such as ``unknown field `direction`, expected one of `keys`, `screenshot_ref`, …`` for `scroll`. It used to drop the field and fail on another one, or act without it. Every tool's schema says so with `additionalProperties: false`.
- `close_window` takes the window as `window_id`, like every other tool. `id` still works.
- `wait_for` also takes `until: {"screen_stable": {}}`. JSON sent inside a string, such as `"\"screen_stable\""`, fails with the forms that work.
- Calls refused for their arguments before the tool runs are written to the audit log as `invalid_arguments`, with the names of the fields they were given and never their values.
- The `noctalia` tool's description says that every call needs the lease, even `["--help"]` and `["plugins", "list"]`.

### Fixed

- Typed text puts a symbol on a spare key when the layout has it only on a key Chromium drops. US maps have `€` only on `<I443>` (evdev 435), so `€` typed into Chromium and Electron apps arrived as nothing. A symbol also on a normal key types there, so US `$` uses Shift+4 instead of `<I442>`, which Chromium dropped too.
- The Safety page said the pointer tools don't check whether windows moved since the screenshot. They have refused such a screenshot with `layout_changed` since 0.1.2.
- A screenshot that waits for the screen to settle, an action's `screenshot: true` or `wait_for` `screen_stable`, compares raw pixels and counts the screen as still when two captures in a row each differ from the capture before them both by at most 0.5 % of the pixels. A clock, a CPU graph, a spinner or a caret no longer keeps the wait going until the 1.5-second limit. A window still sliding into place adds up past that and keeps the wait going. The screenshot's metadata says in `changing` how much changed last.
- `focus` and `release_desktop`'s `restore_focus` that time out with no window focused, and keyboard and element tools refused with `focus_mismatch` because no window has keyboard focus, say in `detail` what may hold it: Noctalia's open panel, or the layer-shell surfaces niri lists that take keyboard focus, and that `shell_panel` or `key` `Escape` with `expect: "none"` closes it.
- A `wait_for` `window` condition that times out lists the windows that opened during the wait in `opened`, with their `app_id`, so a wrong `app_id` such as `helium-browser` for `helium` shows.

## 0.1.5 - 2026-10-18

### Changed

- The Noctalia plugin's panel puts Stop in its status card, beside the settings button. It shows only while an agent holds the desktop, for five minutes after one gives it back, since agents often take it again before asking you something, and while `watch` is down. It used to sit in the Activity heading, where it read as stopping the feed, and showed while no agent was there.
- An agent's consecutive key presses, each within 30 seconds of the last, share one row in the panel's feed, such as `Pressed 4 keys`, with each call's keys under it and in its tooltip. A failed press, another agent or any other call starts a new row.
- With more than three rows, the panel's agent list shows only the driver, or the first agent while none drives, then `and N more`, where it showed three. Its heading counts the connected agents and says once how many are on an old build; each of their rows says `old build`, where it said `old build, restart it`.
- The audit log, and so `watch`, names a `noctalia` call's command, with Noctalia's description of it, when its first argument is exactly a command in Noctalia's own `noctalia msg --help` list, and for `plugin` the plugin's id when `plugins list` lists it. The other arguments are still logged only as their count and lengths, never their text. The server reads both lists from Noctalia right before it sends a call that holds the lease and has valid arguments, and waits at most 300 ms for them. The Noctalia plugin's activity feed shows that description, such as `Toggle caffeine (idle inhibitor)`, or `Sent an event to ayagmar/obs-control` for a plugin call, and `Sent a Noctalia command` as before when the log names neither.

### Fixed

- The panel's unfolded agent list scrolls within its height. It grew to fit every row and pushed the activity feed down to two rows with eight agents connected.
- Two sessions of one agent in one project showed as two identical rows in the panel's agent list. They now share a row that counts them, such as `2 sessions`, with their PIDs in its tooltip. The driver keeps a row of its own, and servers whose agent `watch` couldn't name never share one.
- The bar tooltip separates the last call from its time with `·` instead of a comma, so `Pressed Escape, c` no longer reads as one more key. Connected agents and old builds share one line.

## 0.1.4 - 2026-10-18

### Added

- The install script also offers to register the server in Amp, GitHub Copilot CLI, Gemini CLI and Qwen Code when they are on `PATH`, through each one's own `mcp add` at user scope. The client setup page gives their commands, and the config entries for Cursor CLI, Factory Droid, OpenCode, Kilo Code CLI, Goose and Crush, which the script leaves to you.

### Changed

- The install script is meant to be piped into `sh`: `curl -fsSL https://github.com/ayagmar/niri-computer-use/releases/latest/download/install.sh | sh`. The whole script is now one brace group, which `sh` reads to its end before running any of it, so a download cut short runs nothing, and an agent's `mcp add` that reads stdin can't take the script's own lines. Its questions are still read from the terminal.
- With more than four agents connected, the Noctalia plugin's panel shows the driver and two more, and folds the rest into `+N more`, with how many of them are on an old build, so the activity feed keeps its room. Unfolded, the list scrolls within about four rows, and it folds again whenever the panel opens.

### Fixed

- The install script no longer stops, after installing, when its output is a terminal it can't open, such as a session with no controlling terminal. It registers in no agent then, and prints the commands to run by hand.
- The Noctalia plugin sends failed-action notifications at normal urgency rather than critical, since agents retry most failures. Stuck input, and a Stop or Resume that failed, stay critical.
- When `watch` exits with an error of several lines, before or after it started, the Noctalia plugin's panel shows its first three lines rather than only the last, so a panic shows its message instead of the `RUST_BACKTRACE` note after it.
- `set_element_text` refuses text ending with tool-call closing tags such as `</parameter>` or `</invoke>` that no opening tag earlier in the text balances, with `leaked_tag` and the tags named in `detail`, as `type_text` has since 0.1.2. It used to set such text, so a leaked tag landed in the field. Nothing is set; send the text again without the tags.

## 0.1.3 - 2026-10-17

### Added

- `niri-computer-use watch` prints what agents are doing on this niri instance as JSON lines: who holds the lease and since when, in which project, whether the stop flag or the input-dirty marker is set, which agents have a server on it and whether an update replaced that server's binary, and each tool call the audit log records, the last 20 marked `backlog`, for a shell such as Noctalia to show. It never connects to niri, and the lines hold only what the audit log and the lease record hold.
- A Noctalia plugin, in `noctalia/niri-computer-use`, shows which agent drives the desktop and what it does. Its bar widget breathes in the accent colour with the agent's name while one drives, and right-click stops agents or resumes them. Its panel shows who drives, in which project and for how long, every connected agent with the ones left on an old build marked, a Stop button, a settings button and the last 50 calls in words, opening on the newest and following new ones. Its desktop glow frames the output behind the windows while an agent drives, and it notifies when an agent takes the desktop, once for an agent that takes it back within five minutes, when agents are stopped, when input may be stuck and when an agent is left on a replaced build; failed actions only when turned on. What it finds when it starts isn't announced. It reads `niri-computer-use watch`.
- The install script installs the Noctalia plugin from the same release to `~/.local/share/niri-computer-use/noctalia/niri-computer-use` and, when `noctalia` is on `PATH`, links it into Noctalia's plugin directory and prints the command that enables it. It doesn't enable it.
- After an update, the install script lists each `niri-computer-use serve` still running the binary it replaced, by PID and the agent that started it, so you know which agents to restart or reconnect.

### Changed

- A server that requires the shared engine, and couldn't reach it or was refused when it started, now tries again on every call, starting an engine if none runs. Once the cause is gone, such as an engine of an older build that exited after its last client, the next call is served, without restarting the MCP server. Until then every call fails with `engine_unavailable` as before. A cause no call can fix, such as a socket path over 108 bytes, still needs a restart.
- Such a server no longer lists `noctalia` while `unrestricted` is off, and once a call reaches an engine it sends `notifications/tools/list_changed`, since the engine leaves out the tools that need Noctalia or an accessibility bus when they aren't there.

## 0.1.2 - 2026-10-16

### Added

- `shared = "required"` in the policy file, or `NIRI_COMPUTER_USE_SHARED=required`, makes the shared engine required, so every client of a niri instance is served by one process, with one crash guardian, niri event stream, accessibility connection and audit writer. A server that can't reach the engine, or that the engine refuses, no longer serves its client on its own: it lists the client's tools, every call fails with `engine_unavailable`, and the `detail` and the server's stderr say why, such as the engine's socket path and the connect error, or the refusal. Restart the server once the cause is fixed. A wrong `NIRI_COMPUTER_USE_SHARED` doesn't drop a requirement the file sets, and neither does a mistake elsewhere in the file, even one that stops it parsing as TOML. `status.shared` reports the setting (`on`, `off` or `required`) and why the variable was refused. The default, `true`, still falls back to serving the client on its own.
- `wait_for` waits on a window's accessible elements: `{"element": {"window_id", "role", "name_contains", "state", "absent"}}` waits until an element `elements` would list, with that role, name text and state (a name from a JSON listing's `states`, or `disabled` for one without `sensitive`), is there, or with `absent: true` until none is. A met wait for an element that appeared returns its `element_ref` while you hold the lease, with `unbound` or `unmappable` when `elements` would give them, and no ref, with the reason in `detail`, when a walk cut short can't tell it from a look-alike further on. A window that closes ends the wait as `window_gone`, and one whose app isn't on the accessibility bus as `not_accessible`. A walk cut short, or one that skipped an object gone by the time it read it, and with it everything under it, never counts as proof that the element is gone, and a wait that times out after such a walk says which in `detail`. A walk that the wait's own end cut short, one that began with less than its three-second budget of the wait left, doesn't count against the walk before it, so a wait whose earlier walks read the whole tree doesn't time out saying the last walk was cut short. A walk that began earlier and ran out of its own budget still says so, even when it came back after the wait's end. The audit log keeps the role and state names and the length of `name_contains`, never the text.
- `activate_element` and `set_element_text` return `effect`: `seen` when reading the element back showed the action's effect, `differs` when a field holds other text than was sent, `none_seen` when nothing the server can read changed, and `unverified` when it couldn't be read. A read that fails after the action went out is `unverified` with the reason in `detail`, never an error. The audit log keeps `effect` beside `observed`.
- `activate_element` reads the value of an element that has one, such as a slider or spin button, before and after, and says in `element.value_changed` whether it changed, never the value. It also compares the element's name, and says in `element.name_changed` whether a button relabelled itself, never either name.
- When `elements`, `wait_for`'s element condition or an action's `element_changes` finds the window of a Chromium, Electron or CEF app off the accessibility bus and the session's accessibility is off, the server turns it on by registering an AT-SPI event listener, as a screen reader does, and holds it on until the server ends, however it ends. Chromium, Electron and CEF apps join the bus only when it was on when they started, so apps started after that are listed; one already running needs a restart, and `not_accessible`'s detail says to ask the user first. The server tells such an app by the files Chromium maps (`icudtl.dat` or `v8_context_snapshot.bin` in `/proc/<pid>/maps`); for any other app off the bus, such as a terminal, or a process it can't inspect, it changes nothing and gives the plain `not_accessible`. The server never writes `org.a11y.Status`, leaves accessibility alone when something else turned it on, and needs at-spi2-core 2.61 or later: with an older one it lets go and says so. `turn_on_accessibility = false` in the policy file turns this off. `status.accessibility_switch` says what the server did (`off`, `on`, `turning_on`, `unsupported`, or `let_go` once accessibility read off while the server's listener held it on, which two overlapping calls don't cause), and `status.policy.turn_on_accessibility` whether it may. The launcher also sets GSettings' `toolkit-accessibility` to true, as it does when a screen reader starts, and that stays after the server ends; `gsettings reset org.gnome.desktop.interface toolkit-accessibility` undoes it.
- `elements` asks a Chromium window for its page's tree when it shows none, as Chromium builds it only once an assistive technology asks. That listing has `building: true`, or `the app built its tree just now` in the compact header: list again a second later for the page.

### Changed

- `set_element_text` on an editable field that has no `EditableText` interface, as Chromium's text fields are, fails with `text_not_settable` instead of a plain `invalid arguments:` that read as a mistake to fix and send again. Its detail says to focus the field with `activate_element`, then send the text with `type_text`, pressing `ctrl+a` with `key` first to replace what it holds. A password field without `EditableText` is `secret_field`, and an element that isn't editable is still an argument mistake.
- A shared engine that refuses a client's server because it runs another build says what to do. After an upgrade, a client still running the old build whose engine ended meets an engine of the new build, which refuses it for as long as it runs: its `engine_unavailable` detail now names both builds and says to restart that MCP client, where it said only that the engine runs another build, and the bridge no longer adds that the next call tries again. An engine whose own file was replaced since it started says to restart the clients it serves. When neither file was replaced, as with two installs on different paths, where restarting either client runs its build again, it names both files and says to point the clients at one. Bridges name their release in the hello, which engines of 0.1.1 and older ignore.
- A client started after an upgrade beside a shared engine of 0.1.1 or older, which it is served standalone beside, says in `status.engine.fallback` that engine's PID and what to do, from the files that engine and this server were started from: when an upgrade replaced the engine's file, that it serves the clients started before the upgrade until the last of them ends, and to restart those clients to end it; when both builds are still installed, to point the clients at one file. That engine's own words say only that it runs another build, or, from 0.1.0, `the bridge speaks hello Some(3); this engine speaks 2`. Engines now name their release in a refusal, so a bridge adds this only to an older engine's.
- `elements` reads the elements inside a container of more than 64 children, such as a long list, table or grid, after the rest of the window, and lists them after it. A window whose walk is cut short inside such a list still lists its own controls, such as the toolbar's and the buttons below the list, where it used to stop before them; those outside a named list row are `unbound: cut_short`, since the unread part may hold a look-alike.
- `elements` reads up to 20,000 objects of a window's tree, up from 2,000. One long list, table or grid used to stop the walk before the rest of the window, so its other controls were never listed, or were `unbound: cut_short`. In nested GTK 3, GTK 4 and Chromium windows of 2,218 to 15,022 objects, the whole tree now reads in 0.15 to 0.82 s and every control outside the list has a bound ref; listing such a window takes that long. A window over 20,000 objects, or too slow to read in the three seconds, is still cut short.
- `type_text` refuses text, typed or pasted, that ends with tool-call closing tags such as `</parameter>` or `</invoke>` that no opening tag earlier in the text balances, each opening tag balancing one closing tag, with `leaked_tag` and the tags named in `detail`. Models sometimes leak their own tool-call markup into the end of a long argument. Nothing is typed or pasted; send the text again without the tags.
- `set_element_text` reads the field's text back and compares it with the text sent, instead of comparing only the character count. A field that reformats or masks text without changing its length is now `differs`, not `matched`. Neither text is returned or logged.

### Fixed

- A pointer tool no longer fails with `lock_stale` before its first input, or stops partway with its button released, when nothing was slow. Each look in a gesture kept a lock read under 250 ms old and then required it to be under 250 ms old at its end, so a read that turned 250 ms during the look itself stopped the gesture. Such a look now reads the lock state again and looks once more. A gesture still stops when that second look is too slow.
- A pointer tool aimed at pixels of a screenshot no longer goes out after the windows on that output moved since the capture. The ref was checked only against its age and its output, so two clicks 5 and 12 seconds after their screenshots pressed wherever the screen had moved to: in a real session, the user resized the browser and later focused their terminal beside it, and the agent's clicks went to the browser's blank margin and into the terminal. The call now fails with `ref_invalid` and `layout_changed` when the overview, the output's workspace, a window on it opening, closing, moving or resizing, or the window niri scrolls the view to changed after the capture began, even if the change was undone since, and says which. niri's initial state counts as a change on every output, both when the server starts reading niri's events, since niri may be moving windows then, and when the event stream reconnects, since niri may have moved windows while it was down. It checks when the call starts and again right before the first input and, for a drag, before the press, so with niri's `focus-follows-mouse` on, a drag that starts over a window without focus stops before the press as `uncertain`: its own motion focused the window, which may scroll the view. A drag from a new screenshot then goes through. A reconnect of the event stream while the call gets ready fails it with `unknown_ref`, as at its start. niri doesn't report everything that moves what is under a pixel, so the check can't see the view scroll with nothing else changing, as with `center-column`, a floating window raised over another, a layer-shell surface such as a notification opening over the target, or a change inside a window. A change less than a second before the capture counts too, since niri may still have been animating it and the image may show windows on their way, unless the screenshot waited for the screen to settle and it stopped changing after the change, as `screenshot: true` on an action does; that refusal's `detail` names those settled screenshots, since a plain one taken right away is refused again. So in the server's first second a plain screenshot can't be aimed at by pixel, while a settled one can, and an aim at an `element` is refused by its own check as `not_showing`, since the view may still be moving. An aim at an `element` is otherwise placed again just before the gesture and isn't affected by this check.
- A wait for the screen to settle, `wait_for` with `screen_stable` or an action's `screenshot: true`, no longer pushes the agent's screenshot refs out. Each capture it took kept a ref, about ten a second, and a lease keeps 64, so in a real session a 25-second `wait_for` on a screen that never settled, with the agent's own terminal spinner on it, dropped the screenshot the agent had just looked at, and its zoom failed with `unknown_ref`. Only the capture the wait returns keeps a ref now, so a settle wait pushes out at most one of the agent's 64, and a wait that returns no screenshot none.
- `key` and `type_text`, typed or pasted, no longer answer `sent` when niri moved keyboard focus to another window in the last moments of the call. niri sends keys to the window it has just focused before its event stream reports the move, and the check before each key reads that stream, so a move near the end went unseen: in a nested run, niri sent a key to a modal dialog's own surface and the call answered `sent` with `focus: matched`. After the last key the server now asks niri which window has focus, and reads the events its stream has passed on by then; focus elsewhere makes the call `interrupted`, and no answer from niri makes it `uncertain`. It also asks niri before the submitting `Return` and before the last key of a `key` call, such as the `Return` of `["Down", "Down", "Return"]`, and sends nothing more when focus moved, by niri's answer or by what its event stream reported while niri answered, so `Return` doesn't confirm a dialog that just took focus. When niri answers so slowly that the lock state's last read is over 250 ms old by then, the server reads the lock state again and asks niri once more, rather than failing that key with `lock_stale` after the others went out. An `interrupted` call whose keys went out says in `detail` how many and that some of them may have reached the window that took focus. An app that hands keys to a dialog of its own before niri has focused it, as GTK does with a modal dialog, still gets `sent`: niri sent the keys to the window `expect` named, and only `changes` shows the dialog opening and taking focus afterwards.
- A Chromium page's elements no longer get a `layout_box` in the output's pixels. With `prefer-no-csd` in niri's config, Chromium's frame is the window's size, so its elements were placed, but Chromium gives a web page's coordinates in the output's pixels: at scale 1.5 a field at 106,106.7 200×29.3 was listed at 126,126 300×45, and a click by its ref landed below it. The server now divides a page's coordinates by the output's scale when the page's document is the size of the view holding it times that scale, and checks that again right before a pointer tool aims. When the document matches neither unit, the element is `unmappable: page_scale_unknown`, and an element whose centre is outside its page's document, as under the browser's toolbar once the page is scrolled, is `not_showing`. The off-page refusal applies at every scale, scale 1 included; nothing else changes at scale 1, or with Chromium's own title bar and shadow, which still give `frame_size_mismatch`.
- A screencast event the server can't parse no longer stops its event stream. niri built from `main` after 26.04 reports each `grim` capture, including the server's own screenshots, as a screencast of a kind `niri-ipc` 26.4.0 doesn't know. The server stopped its stream at the first screenshot and was read-only until it restarted; it now drops screencast events unread, as it never reads screencasts. Any other event it can't parse is handled as before: the first makes it reconnect, a second stops the stream.
- An event that `niri-ipc`'s state panics on, such as niri closing a window it never reported, now stops the event stream for good as `schema_incompatible`, so actions are refused with `read_only` and `desktop_state` and `wait_for` fail with `upstream_error` and the panic's message. The panic used to end the stream's reader without a word: `status` kept saying `connected` while the state stopped changing, and actions went on with it.
- The input-dirty marker 0.1.0 writes while `wtype` runs is read again, as a `running` marker naming its input child, where 0.1.1 read it as unreadable. A server beside a 0.1.0 server still typing says that server's input may still be finishing, as for any other server's marker, and `recover` ends the `wtype` child the marker names, if it is still that process, and then sends zero modifiers from a fresh virtual keyboard, since a physical key doesn't always release a modifier `wtype` pressed, or says it couldn't, before it asks for the manual check. 0.1.1's `recover` cleared the marker and left the child running: in a nested 0.1.0 engine killed mid-`type_text`, its `wtype` child still ran when `recover` cleared the marker. `recover` never takes PID 1, init, for that child. It opens a pidfd for the child before it checks the child's start time and kills the child only through it, never its process group: 0.1.0 ran `wtype` itself, which starts no processes, so ending it ends the typing, and a process that took the child's PID after the check is never ended.
- A paste's key no longer goes out to a window that took focus while the clipboard keeper admitted it. `expect`, focus and the deny list were checked before the server asked the keeper to admit the key, which can take up to half a second, and not again after, so the key could reach the window the user focused meanwhile, even one of an app the deny list names. Once the keeper admits the key, the server now checks again right before it: it reads the lock state again if its last read began more than 250 ms ago, reads the events niri reported meanwhile and asks niri itself which window has focus, since niri can send a key to a window it has just focused before its event stream says so. Focus or the keyboard layout moving ends the call `interrupted` with `pressed: 0`, a denied app fails it with `app_denied`, and a locked screen or a stop fails it as before any key. Either way the key isn't sent and the clipboard is put back.
- An action's `element_changes` no longer reports elements as removed when an object went away while the walk after the action read the tree: the walk skipped that object and everything under it, so their elements looked gone, though a replacement may still hold them. It now says `unknown: nodes_gone`.
- `elements` no longer fails on a window with an object of more children than the app will list, as GTK 3 apps refuse to list more than 65,536 with `InvalidArgs`, such as a tree view of 22,000 rows of three columns. The walk reads on past that object, and the listing is cut short with `capped_reason: children_refused`, so the window's controls outside named rows are listed `unbound: cut_short`. An action's `element_changes` for such a window says `unknown: children_refused`.
- `elements` no longer binds a ref by a count of look-alike elements it didn't finish. A control outside any list row whose twin, with the same role and name, lay past the listing's `limit` got a ref that could act on the wrong record, as with two `Delete` buttons of a list put on the bus without rows. The walk now reads on past `limit` to the end of the window's tree, so such a control is `unbound: repeated`. When the walk still didn't read the whole tree, cut short at its 2,000 objects or its three seconds, or because part of the tree went away while it read, a control in no row is `unbound: cut_short`, and every tool refuses its ref: aim at its pixels. In a window that large, only elements in a named list row keep a ref that acts. A listing now reads the whole tree whatever its `limit` and filters: about 55 ms for 600 objects and 190 ms at the cap in a nested GTK 4 window, where a listing that stopped at its limit took 2 to 13 ms.
- A screenshot or element ref spelled with a sign or leading zeros in its number, such as `shot-<tag>-+1` or `shot-<tag>-01`, no longer names the ref issued as `shot-<tag>-1`. Such a ref worked while the audit log recorded it as `invalid_ref`; it is now `unknown_ref` or `element_stale`, as any ref the server didn't issue.

## 0.1.1 - 2026-10-14

### Added

- `install.sh` offers to register the server in each of Claude Code, Pi and Codex it finds on `PATH`, through the agent's own `mcp add` command, asking per agent when its output is a terminal. `NCU_REGISTER=1` registers in all of them without asking, `NCU_REGISTER=0` in none. An agent that refuses doesn't fail the install; its command is printed under the next steps.

### Changed

- `key`, `type_text` and a paste's key always go through the server's own virtual keyboard with the compositor's keymap, and `click`, `drag` and `scroll` take held `keys` without configuration. In Chromium and Electron apps, wtype's keys lost spaces and punctuation and missed shortcuts such as VS Code's `ctrl+s`; the native keyboard types text your layout has exactly. Symbols your layout lacks, such as accented letters, Greek, Cyrillic or arrows on a US layout, arrive exactly there too, because native puts them on keycodes Chromium knows, F13 to F24 among them. Emoji and other characters outside the Basic Multilingual Plane still arrive as other characters there, so paste them.
- Native text with more distinct symbols the layout lacks than the keymap has spare keycodes, 14 in a US layout, is typed in parts, each with a temporary keymap of its own, instead of refused.
- A native `key` combination, a paste's key included, that the active layout lacks goes out in another of your layouts that has it, so `ctrl+v` and `ctrl+s` work while a layout such as Russian is active.
- After a native call, a lock that was on, such as Caps Lock or Num Lock, reads as off in the focused application until you press a modifier or lock key, the keymap changes or focus moves.

### Removed

- The `wtype` keyboard. `NIRI_COMPUTER_USE_KEYBOARD` is no longer read, and any value is ignored rather than refused, since 0.1.0's docs told you to set it to `native`; a setting of `wtype` now gets the native keyboard. `wtype` is no longer needed at run time, and `status.binaries` lists only `grim` and `notify-send`.
- `recover` no longer ends an input program or offers to end your `wtype` processes. It releases the keys and buttons the marker names, asks for the manual check, and clears the marker after `yes`. An input-dirty marker 0.1.0 wrote while `wtype` ran can't be read by this version, so input stays blocked until you run `recover`. Restart every MCP client after upgrading, so no 0.1.0 server keeps running beside this one: a marker it writes while typing reads as unreadable here, and sends agents to `recover` until it finishes.

## 0.1.0 - 2026-10-14

The first release: an MCP server over stdio that lets an AI agent read and act on a niri 26.04 desktop.

### Upgrading

- If you run a source build of `main`, end every running `niri-computer-use` process (servers, bridges and shared engines) before installing this one, then start your clients again. `pgrep -a '^niri-computer-u'` lists them. Older builds of `main` kept their runtime directory under `XDG_RUNTIME_DIR`, so an old and a new server on one niri would share neither the lease nor the stop flag. Tools were also merged and renamed during development; link or copy `skills/niri-computer-use` again so your agents read the current names.

### Added

- `niri-computer-use serve`, an MCP server over stdio, and the commands `status`, `stop`, `resume`, `recover` and `--version`.
- 22 tools. Reading, with no lease: `status`, `desktop_state`, `screenshot`, `elements` and `wait_for`. The lease: `acquire_desktop` and `release_desktop`. Under the lease: `clipboard_read`, and the tools that act, `focus`, `launch`, `close_window`, `niri_action`, `pointer_move`, `click`, `drag`, `scroll`, `key`, `type_text`, `activate_element`, `set_element_text`, and with Noctalia installed `shell_panel`, and `noctalia` when `unrestricted` is on as well. `elements`, `activate_element` and `set_element_text` are listed when the session has an accessibility bus.
- `desktop_state`: windows, workspaces, focus, the overview, keyboard layouts and outputs from niri's event stream, and with Noctalia installed its status as `shell`.
- `screenshot`: one output or a region inside one, through `grim`, as JPEG or PNG, at most 1280 pixels wide unless `max_width` says otherwise. A region of an earlier screenshot, named by its `screenshot_ref`, is captured again at full resolution to read small text. `save_path` writes a PNG under `~/Pictures/niri-computer-use`, or the policy's `capture_dir`, never through a symlink and never over an existing file.
- `elements`: one window's accessible elements over AT-SPI, one line each with an `element_ref`, role, name, states, actions and box in layout coordinates. `activate_element` runs an element's own action and `set_element_text` replaces a field's text, both through the accessibility bus. The pointer tools take an `element` in place of screenshot pixels.
- `wait_for`: waits for a window to appear, close or change its title, or for the screen to stop changing, for up to 30 seconds.
- `focus` a window or workspace, `launch` an app from a policy preset, optionally reusing an open window, and `close_window`. `niri_action` sends any niri action in niri's IPC JSON, such as fullscreen, floating or a column's width, and returns the window's state after it.
- Pointer input through niri's virtual pointer (`pointer_move`, `click`, `drag`, `scroll`), aimed at a screenshot's pixels through a `screenshot_ref` that expires after 60 seconds or when its output changes.
- Keyboard input through `wtype` into the window named in `expect`: `key` presses up to 16 combinations, and `type_text` types up to 1000 characters in parts of 100, with focus and the lock state checked again before each part. `submit: true` presses Enter only once all of the text went out. `via: "paste"` pastes up to 1 MiB through the clipboard and puts the clipboard back afterwards. `NIRI_COMPUTER_USE_KEYBOARD=native` selects an experimental backend on niri's virtual keyboard that checks focus before every key.
- Every action result says whether niri `accepted` the action and what was `observed` after it. `changes` lists what niri saw change, such as windows opened, closed or moved and focus moving, and `element_changes` lists the accessible elements that changed. `screenshot: true` adds a screenshot taken once the screen stopped changing.
- `clipboard_read`: the clipboard's text, under the lease.
- `shell_panel` opens and closes the Noctalia panels `control-center`, `wallpaper` and `tray-drawer`. `noctalia` sends any Noctalia command and is listed only with `unrestricted` on.
- A policy file at `$XDG_CONFIG_HOME/niri-computer-use/policy.toml` with launch presets (`[[preset]]` with `name`, `argv`, `app_id` and `env`), `deny_input_app_ids`, `capture_dir`, `unrestricted`, `confirm_lease`, `shared` and `tools`. `NIRI_COMPUTER_USE_UNRESTRICTED`, `NIRI_COMPUTER_USE_CONFIRM_LEASE`, `NIRI_COMPUTER_USE_SHARED` and `NIRI_COMPUTER_USE_TOOLS` set the same for one client.
- Tool profiles: `tools = "observe"` lists only the five reading tools, `"act"` leaves out `niri_action`, `noctalia` and `shell_panel`, and `"full"`, the default, lists every tool.
- A shared engine per niri instance, on by default: each client's `serve` relays to one `niri-computer-use engine`, started in its own systemd user scope where systemd allows it. Policy, keyboard backend, `PATH` and working directory stay per client.
- Session discovery: with no `XDG_RUNTIME_DIR`, `NIRI_SOCKET` or `WAYLAND_DISPLAY` from the client, the server takes them from the user's only running niri, so no client needs environment settings.
- The `niri-computer-use` skill in `skills/`, which tells agents how to use the tools, with tool and error tables in `references/`.
- An audit log of every tool call at `$XDG_STATE_HOME/niri-computer-use/audit.jsonl`, with argument metadata and outcomes but no typed text, clipboard, window titles or images, moved aside at 10 MiB with three old logs kept.
- Failures carry a stable error name and the upstream detail; the skill's `references/errors.md` and the documentation site list them.
- The documentation site, with `llms.txt` and a Markdown address for every page.
- Release tarballs for x86_64 and aarch64 Linux with the binary, the skill and the licenses of the crates built in, and `install.sh`, which installs the binary and the skill from one of them.

### Security

- One server at a time holds the lease on a niri instance, an exclusive `flock` in a runtime directory beside niri's socket. Only the holder acts; another session's `acquire_desktop` fails with `lease_held`.
- `niri-computer-use stop`, meant for a niri bind, cancels the running action and takes the lease back until `niri-computer-use resume`. It doesn't connect to niri, so it works while niri hangs.
- Every action goes out within 250 ms of a read of the lock state, from Noctalia and logind, that said unlocked. A locked or unknown state fails with `screen_locked`, and a read that got too old before the call could go out fails with `lock_stale`.
- With `confirm_lease` on, `acquire_desktop` waits for you to choose Allow on a desktop notification sent with `notify-send`. A denial, a dismissal or no answer within 60 seconds fails with `lease_declined`.
- An input-dirty marker is written before input and removed once the input is released. A crash mid-input leaves `recovery_required` until you run `niri-computer-use recover`. A crash guardian beside each server releases held native keys and pointer buttons when the server dies.
- Keyboard and pointer input refuse with `app_denied` while an app on the deny list has focus, and element actions and `close_window` refuse on its windows. `set_element_text` and `activate_element` refuse fields marked as passwords with `secret_field`.
- `launch` only starts presets, and a preset can't start a program that runs whatever follows it, such as `tmux`, `ssh`, `flatpak-spawn` or `docker`. `niri_action` refuses actions that run programs, write files or reach past the layout, such as `Spawn` and `DoScreenTransition`, with `unrestricted_required`. `unrestricted`, off by default, allows both, and lists `noctalia`.
- `clipboard_read` returns only what was copied while the lease was held (`copied_before_lease` otherwise), and never text its owner marked secret for clipboard managers, such as a password copied from KeePassXC (`secret`).
- The name an MCP client gives itself is cut to 64 characters of ASCII letters, digits, spaces and `._-+@` before it labels the audit log, the lease holder and the `confirm_lease` prompt.
